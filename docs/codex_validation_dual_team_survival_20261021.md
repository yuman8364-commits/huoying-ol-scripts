# Codex 验证清单：双队异步调度 + 会员生存 80 分

本分支仅做针对性源码修改，**尚未进行游戏实机验证、打包验收或完整回归**。请先用 Codex 在 Windows 上验证，再决定是否合并。

## 本次行为变化

- 双队各自推进关卡/领奖/下一轮；不再等双方每一轮同步结算。仍然只有一个前台控制者，所有点击继续复用页面/身份/不可逆操作防重门。
- 副本/强者将已验证的每场战斗耗时记录为最近 20 场样本；接近中位数结算时间时缩短观察间隔，自动奖励加时不视为失败。团队运行结束保存 team_timing_summary（观测首战启动间隔、估计重叠时长、总时间）。
- 生存会员账号可以从 80/220 开始；**不按固定场数**声明完成。开战前保存本轮积分基线，结算后必须看到积分增长才提交本场。积分滞后时进入 pending，保留原不可逆动作，禁止再次开战/重复点击。
- 重置后会员可能回到 80/220；只能依靠原满分领奖凭据、重置前截图、重置次数 1→0 等证据核实。仅凭当前 80 分不能断言已重置。
- 后台标签超过 30 秒未采样不再自动构成“画面持续静止 30 秒”；切回后重新观察，连续观察无变化仍会触发看门狗。
- 生存等级 OCR 共享逐帧相关性计算；市场数字边缘图和模板 FFT 复用，不改变点击阈值。
- 普通生产任务默认不装载仅供影子评估的 ONNX 模型。需要模型影子评估时可在 INI 中设置 EnableShadowDetection=1。

## 游戏内验证（由用户进行）

1. 两支互不重叠的现成队伍同时选择组队副本，记录 A 首次确认自动、B 首次确认自动、两队各自开始下一场的时间。确认 A 在后台战斗时 B 可以启动；B 先完成后可以先开下一场。
2. 让一队遇到自动接续的额外奖励关卡，观察另一队是否仍然推进；不因为超过预测战斗时长重复开战/误判通关。
3. 普通 0/220、会员 80/220 账号各完整跑一次生存，再验证是否允许重置、重置后起始积分和第二轮是否真的打到 220 且领取奖励。
4. 用 F12 结束正在结算的生存演习，再重开相同任务，确认 pending 操作不会重复点击。查看日志中的 survival_step_*_score_unverified、survival_pending_progress_observed 及其证据，必要时人工确认。
5. 如果使用的是 exe 而非源码启动，验证源码后**重新构建 exe**；旧版 exe 不包含此分支的改动。

## 实测验收要求

- 账面记录“完成”的每场生存必须有本轮正向积分增长或可信的原始结算对账，最终以 220/220、领奖与回村为准。
- 队伍不能串账号、重复开战或重复领取，未决/掉线情况应保留状态。
- 统计不同队伍的开战间隔、重叠时长与整轮总耗时，和原版本实测对照；本 PR 不预设加速百分比。
- 观测总时间仅作为性能评估；估计完成时间**不得**用作授予完成或点击授权的条件。

如果实机出现积分并非每场都增长、积分延迟超过 4 秒或某些 80 分重置界面不展示剩余次数的情况，请保存相应屏幕与事件日志，在 Codex 中据证据定向调整，不要移除上述防重和身份校验。
